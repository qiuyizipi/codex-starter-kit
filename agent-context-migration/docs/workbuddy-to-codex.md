# WorkBuddy → Codex 完整迁移流程

## 1. 先做只读盘点

记录来源数据根目录、项目路径、项目记忆目录、全局记忆目录和会话归档目录。不要先复制整个用户目录，也不要把临时任务误判为项目。

盘点结果至少包含项目路径、顶层会话、原始 ID、标题、时间、记忆来源，以及子 Agent、工具结果和附件范围。

## 2. 建立迁移清单

为每个项目生成清单，示例见 `examples/manifest.example.json`。清单是迁移的控制面，避免依赖目录排序或自动标题。

## 3. 分离内容层

1. 代码与实验数据：继续使用原项目路径；
2. 项目记忆：复制到目标项目的 `memory/`；
3. 全局记忆：只迁移与该项目有关的部分；
4. 历史对话：原始 JSONL 只读保存；
5. Codex 入口：创建 `AGENTS.md`、`MEMORY.md` 和恢复说明。

## 4. 一对一保留顶层对话

每个顶层会话对应一个独立的目标任务或归档入口。不要把一个项目的 5 个对话合并成一条“项目总结”。项目总结可以额外存在，但不能替代原始会话。

## 5. 增加来源标记

目标任务可以在原标题后追加 `- WorkBuddy`。原始 JSONL 的文件名和内容不改；来源、映射和目标路径写入索引。

## 6. 建立恢复入口

目标 Agent 开始新对话时，先读取：

```text
AGENTS.md → MEMORY.md → 相关 memory/主题文件 → 对应历史 JSONL
```

不要一次性把所有历史对话塞入上下文；按当前问题检索对应会话。

## 7. 验证

执行 `docs/verification.md` 的检查，至少确认数量、标题、项目路径、文件大小、SHA-256、敏感信息和 Codex 可读性。

## 8. 记录限制

目标 Agent 通常无法在 UI 中一比一恢复原始逐轮聊天。应明确说明：迁移的是可追溯历史档案和上下文入口，不是聊天数据库导入。
