# 发布清单

## GitHub 发布前

- [ ] README 能在 5 分钟内说明问题、范围和限制。
- [ ] 文档不声称“完整恢复 UI 聊天”，除非实际验证过。
- [ ] 示例不包含真实 WorkBuddy 数据。
- [ ] 代码、文档和许可证边界已写清楚。
- [ ] 添加 `SECURITY.md`，说明不要提交凭据和私人历史。
- [ ] 添加版本号和变更记录。

## 内容传播

1. GitHub 作为唯一事实源；
2. 发布一篇真实但脱敏的迁移案例；
3. 用短视频展示“多个旧对话 → 多个新任务”；
4. 用 X、知乎、掘金或 Bilibili 做分发；
5. 根据 Issue 和用户反馈再做第二阶段共享记忆系统。

## 商业化边界

基础规范可以开源；真实项目迁移、企业私有部署和托管服务可以作为后续收费方向。公开仓库必须明确许可证，不要把个人数据作为演示材料。
